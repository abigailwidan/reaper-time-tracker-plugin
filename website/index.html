Two halves of one job

Track quietly.
Report clearly.

The background loop is for you: it runs all day and you never touch it. The report is for the person paying the invoice, and it is scoped so one client never sees another client's work.

● Tracking

Background loop

Runs on your machine · start it once

A defer() loop polls once per second to answer one question: is this REAPER window focused? If it is, the clock on the current project runs. It never touches audio.

  • Focus, not idle. Listening back to a take is work. An idle timer would call it inactivity and under-bill you.
  • Per project, not a global total. Switching tabs closes one clock and opens another.
  • Identity survives renames. Projects are keyed by a GUID in the project's own ExtState, never by file path.
  • Save As is caught. A duplicated project is issued a fresh GUID, so clones never inherit hours they didn't earn.
  • Crash-safe by construction. Atomic writes every 45 s, and sessions left dangling by a crash are reconciled at next startup.
  • Noise is discarded. Focus blips under 5 s are dropped; gaps under 15 s merge into one session.
● Reporting

Report & handoff

What the client receives · run on demand

One action reads the log, writes a standalone HTML report, reveals it in your file manager, and offers to open a pre-addressed email draft to send it with.

  • Scoped per send. With more than one project on file, it asks: everything, or just this one?
  • Self-contained. A single HTML file with no external assets. It opens in any browser, on any machine, years from now.
  • Print-ready. A dedicated print stylesheet swaps the panel to white, so the client saves it straight to PDF.
  • Client-ready draft. Addressed by name, period covered, hours in both decimal and h/m, signed off. Client and sender names persist between runs.
  • No account, no SMTP, no credentials. It opens a mailto: draft in your own mail client and you press send.
  • Runs without the extension. Report generation has no js_ReaScriptAPI dependency, so it works on a machine that never tracked anything.

Signal chain

Window focus in,
invoice attachment out

Four stages, each one reading the previous stage's output. Nothing in the chain reaches the audio thread.

in: OS → out: bool

Poll

JS_Window_GetForeground is compared against this instance's main window, once per second.

in: bool → out: seconds

Accumulate

Elapsed time is credited to the active project's GUID. A tab switch closes one session and opens the next.

in: seconds → out: JSON

Persist

Every 45 s the log is written to a temp file and renamed, so a crash mid-write cannot corrupt it.

in: JSON → out: HTML

Deliver

The report action renders the HTML, zips it for attachment, and opens a pre-written draft in your mail client.

The artifact

What the client opens

One HTML file: totals per project with a 24-segment meter, then every session in chronological order with its start, end and duration. The numbers below are a real generated report.

  • Project totals. Hours per project, each with its share of the busiest project as an LED meter.
  • Full session log. Newest first, with the in-progress session marked live so nothing looks retroactively invented.
  • GUID on the record. Each project prints its identifier, so two similarly named projects can never be confused.
  • Nothing to install. No fonts, no scripts, no tracking pixels — the file is the whole report.

Installation

Five steps, no build

Pure ReaScript with vendored dependencies. Nothing to compile and nothing to sign. Needs REAPER 6.82+ and the js_ReaScriptAPI extension for OS window-focus access.

Setup

  1. Get the repo: git clone it, or use Code → Download ZIP on GitHub and unzip.
  2. In REAPER: Options → Show REAPER resource path in finder.
  3. Copy the whole reaper-time-tracker-plugin/ folder into the Scripts folder shown there.
  4. Actions → Show action list → New action ▾ → Load ReaScript…, then load all three files from src/.
  5. Install js_ReaScriptAPI via ReaPack (Extensions → ReaPack → Browse packages) if you don't have it, then restart REAPER.

Run TimeTracker_Background.lua as a startup action rather than a hotkey. lib/ must stay a sibling of src/ — the scripts resolve modules through a relative ../lib/?.lua path. The folder names aren't load-bearing; that relationship is.

Scope boundaries

What it deliberately doesn't do

A tool that sells verifiability doesn't get to be vague about its own edges.

Single machine

Data is local with no cross-device sync. Two workstations produce two logs.

Focus can over-count

Leaving REAPER focused while you're away from the desk accrues time. The session log exists partly so a client can sanity-check an implausible stretch.

Unsaved projects can orphan

An untitled project gets a temporary GUID. Save before closing and its time migrates to a permanent one; don't, and it's stranded in the JSON.

Attachments are manual

mailto: can't carry files, so the zipped report is revealed for you to drag in. The alternative was storing your mail password in plaintext.

Zipped, not raw HTML

Mail clients inline-preview or quarantine bare .html attachments, so the report ships as time_report.zip.

Commas are stripped from names

REAPER returns dialog fields comma-separated, so a comma in a client name would split the field. It becomes a space rather than mangling the name.
